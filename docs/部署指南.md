### ⚠️ Node 版本要求很严，不要用 apt 默认源

| 来源 | 版本 | 是否可用 |
| --- | --- | --- |
| Ubuntu `apt install nodejs` | 18.x | ❌ **Vite 8 拒绝启动** |
| NodeSource 22.x | 22.18+ | ✓ |
| NodeSource 24.x | 24.12+ | ✓ |

`package.json` 里写的是 `"engines": { "node": "^22.18.0 || >=24.12.0" }`，
而 Vite 8.2.2 自身要求 `^20.19.0 || >=22.12.0`。

**装 Node（NodeSource，系统级）**：

```bash
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt install -y nodejs
node -v          # 确认 >= 22.18
```

**或 nvm（用户级，不污染系统，更适合一次性构建）**：

```bash
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.1/install.sh | bash
source ~/.bashrc
nvm install 22 && nvm use 22
node -v
```

> Node **只在构建时需要**。`npm run build` 产出纯静态 `dist/`，
> 线上由 nginx 直接服务，运行时不需要 Node。

缺 node 时（Ubuntu/Debian）：

```bash
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs
```

缺 python3-venv：

```bash
sudo apt install -y python3-venv python3-pip
```

## 五、nginx —— 三处必须改

### 5.1 现有配置（旧项目的，不能照抄）

```nginx
server {
    listen 80;
    server_name _;

    location / {
        root /var/www/smart;
        index index.html;
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:8080/;   # ← 尾斜杠：会剥掉 /api
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

### 5.2 三个坑

| # | 问题 | 后果 |
| --- | --- | --- |
| 1 | `proxy_pass ...:8080/` 末尾有 `/` | nginx 把 `/api/` 前缀替换成 `/`，后端收到 `/meta` 而不是 `/api/meta` → **全线 404** |
| 2 | 缺 `proxy_buffering off` | SSE 被 nginx 缓冲，前端**一直白屏**，直到整个响应结束才一次性吐出 |
| 3 | `proxy_read_timeout` 默认 60s | Agent 工具链（搜索+排程+润色）常超 60 秒，**连接被切断** |

### 5.3 修正后的配置

```bash
sudo vim /etc/nginx/conf.d/你的站点.conf
```

```nginx
server {
    listen 80;
    server_name _;

    location / {
        root /var/www/smart;
        index index.html;
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:8080;      # 去掉尾斜杠

        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # ---- SSE（Agent 流式输出）必需 ----
        proxy_http_version 1.1;
        proxy_set_header Connection '';
        proxy_buffering off;
        proxy_cache off;
        chunked_transfer_encoding off;
        proxy_read_timeout 300s;
        proxy_send_timeout 300s;
    }
}
```

静态部分（`root` / `index` / `try_files`）**一行都不用改** ——
双入口产物天然适配：

| 请求 | nginx 行为 | 命中文件 |
| --- | --- | --- |
| `/` | 回退 `/index.html` | 移动端 |
| `/pc/` | 目录存在 → `index` | `pc/index.html` |
| `/assets/*.js` | 直接命中 | 构建产物 |

### 5.4 校验并重载

```bash
sudo nginx -t
sudo systemctl reload nginx
```

## 七、托管后端进程

用 systemd 而不是 `nohup`，保证崩溃重启、开机自启。

```bash
sudo tee /etc/systemd/system/ai-travel.service >/dev/null <<'EOF'
[Unit]
Description=AI Travel Assistant Backend
After=network.target

[Service]
Type=simple
User=admin
WorkingDirectory=/opt/ai-travel/backed
EnvironmentFile=/opt/ai-travel/backed/.env
ExecStart=/opt/ai-travel/backed/.venv/bin/uvicorn app.main:app \
    --host 127.0.0.1 --port 8080 --workers 1
Restart=always
RestartSec=3
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable --now ai-travel.service
sudo systemctl status ai-travel.service --no-pager
```

> **为什么 `--workers 1`**：SQLite 单写者 + 内存里的 Agent 会话状态，
> 多 worker 会各自持有独立内存，会话会串。要扩并发得先把这两层改成共享存储。

## 八、验证

```bash
# 后端直连
curl -s http://127.0.0.1:8080/api/meta | head -c 300

# 经 nginx（这一步验证 proxy_pass 尾斜杠修对了）
curl -s http://127.0.0.1/api/meta | head -c 300

# 前端
curl -sI http://127.0.0.1/
curl -sI http://127.0.0.1/pc/

# 流式输出（验证 buffering 关掉了：应该逐块吐出，不是等完才给）
curl -N -X POST http://127.0.0.1/api/agent/chat \
  -H 'Content-Type: application/json' \
  -d '{"message":"苏州两天，喜欢园林"}'
```

浏览器验收：

1. 打开 `http://<公网IP>/` → 移动端首页，绿色主题，卡片有阴影
2. 打开 `http://<公网IP>/pc/` → 桌面端，首屏是登山者照片 + 三行衬线文案
3. 试「AI 助手」→ 应看到工具调用逐步出现（**不是等 30 秒后一次性出现**）
4. 试「上传攻略图」→ 应能提取地点并显示核对结果
